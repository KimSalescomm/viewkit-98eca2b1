# 일산본점 접속 집계 기준 설명

## 확인한 실제 데이터

- 대상: `page_views` 테이블, `store_id = 'ISB'`(일산본점)
- 기간: 2026-08-12 00:00 ~ 2026-08-22 00:00 (KST)
- 쿼리 결과:
  - 총 기록 행수(`페이지뷰`): **721**
  - 고유 세션 수(`방문`): **493**
  - 실제 기록 범위: 08-12 10:00 ~ 08-20 18:54 (UTC)

→ 사용자가 언급한 "방문 493회, PV 721회"는 DB 원본 집계 그대로이며, 별도의 추정/보정 없이 산출된 값입니다.

## Counting 기준

### 1. 페이지뷰(PV) = 721
- `page_views` 테이블에 INSERT된 행(row) 1개 = PV 1회
- 페이지를 이동할 때마다 기록되며, 한 세션 내에서 여러 페이지를 보면 PV는 누적됩니다.
- 단, 아래 중복 방지 규칙이 적용됩니다.

### 2. 방문(세션) = 493
- 같은 `session_id`를 가진 기록을 하나의 방문으로 집계합니다.
- 세션은 브라우저 `localStorage`에 저장되며, **마지막 활동으로부터 30분 이내**면 동일 세션으로 유지됩니다.
  - 브라우저를 껐다 켜도 30분 이내면 같은 세션으로 처리될 수 있습니다.
  - 30분 이상 아무런 페이지 이동이 없으면 다음 접속 시 새 세션으로 분리됩니다.

### 3. 중복 제거 / 제외 규칙
- 동일 경로(같은 페이지)는 **10분 간격**으로만 재기록됩니다.
  - 예: `/product/tv`에서 1분 뒤 다시 `/product/tv`로 오면 PV/방문에 추가되지 않습니다.
  - 10분 이상 지난 뒤 다시 오면 추가됩니다.
- React StrictMode 등으로 인한 **3초 내 동일 경로 중복 호출**은 무시됩니다.
- `SC`(관리자), `KOR`(유관부서) 계정은 집계에서 제외됩니다.
- 지점이 설정되지 않은 상태(최초 진입 시 모달 노출 단계)에서는 기록되지 않습니다.

### 4. 기간 산정 방식
- `created_at`(기록 시각) 기준으로 필터링합니다.
- "8월 12일부터 21일까지"는 08-12 00:00 ~ 08-22 00:00 범위로 해석됩니다.
- 현재 DB에는 08-20 18:54까지의 기록만 존재하므로, 08-21 데이터는 아직 거의 없는 상태입니다.

## 요약

| 항목 | 정의 | 일산본점(8/12~8/21) |
|------|------|---------------------|
| 페이지뷰 | `page_views` 총 행 수 | 721 |
| 방문 | 고유 `session_id` 수 | 493 |
| 세션 기준 | 마지막 활동 후 30분 TTL | - |
| 중복 제거 | 동일 경로 10분 간격 | - |
| 제외 계정 | SC, KOR | - |

추가로 기간을 좁히거나(예: 특정 하루), 경로(path)별 세부 내역이 필요하면 별도 쿼리로 확인해 드릴 수 있습니다.
