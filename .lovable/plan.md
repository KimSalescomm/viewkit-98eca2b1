# 인기콘텐츠 영역 + 홈 리디자인 (1안: 미니멀 프리미엄)

## 목표
1. 홈(제품 선택) 화면을 스크롤 없이 한 화면에 들어오는 고정 캔버스로 만든다.
2. 헤더 아래에 조회수 기준 인기콘텐츠 슬라이드(3~5개)를 추가한다.
3. 제품 카드를 미니멀 프리미엄 스타일로 정리한다(상단 컬러 띠 제거).

## 확정된 디자인 방향 (1안)

- 베이스: 화이트 + 라이트그레이(#F3F4F6), 포인트 컬러 **#FD312E**(브랜드 레드).
- 좌측 상단 **VIEW KIT 로고 락업**: 텍스트 로고 형태(굵은 산세리프, 타이트한 자간)로 배치하고 색상은 #FD312E 적용. 기존 중앙 "VIEW KIT" 라벨은 로고로 승격되어 헤더 좌측으로 이동.
- 헤더 우측: 기존 유틸(SC / 모바일에서 보기 / 뷰킷 소개 / 세로모드 / 콘텐츠 요청)을 라이트 톤 필 버튼으로 정렬.
- 히어로: "어떤 제품부터 보시겠어요?" 대형 볼드 + 부제 라이트 그레이.
- 인기콘텐츠: 다크 이미지 카드(그라데이션 스크림 + 하단 텍스트), 제품명은 레드 캡션, 특장점 제목은 화이트.
- 제품 카드: **상단 컬러 그라데이션 띠 제거**. 화이트 카드 + 얇은 그레이 보더 + 큰 라운드, 상단 정사각 이미지 영역(라이트그레이 배경), 하단 제품명(볼드) + 설명 1~2줄. 아이콘은 텍스트 옆 작은 크기로만 유지하거나 생략.
- 섹션 제목 "제품별 특장점"을 제품 그리드 위에 노출.

## 1. 인기콘텐츠 데이터 (조회수 자동 집계)

이미 `page_views` 테이블에 경로별 방문 기록이 쌓이고 있다(`/product/tv/feature/1` 형태, 지점 계정만 기록, SC/KOR 제외).

- 백엔드에 집계 함수를 추가해 상위 특장점 경로와 조회수를 한 번의 호출로 받아온다(서버 집계).
  - 입력: 기간(기본 최근 30일), 개수(기본 5)
  - 출력: `path`, `views`
  - `/product/{productId}/feature/{featureId}` 패턴만 대상
- 프런트에서 경로를 `products.ts` / `features.ts` 데이터와 매칭해 제품명·특장점 제목·썸네일을 붙인다.
- 현재 지점에서 볼 수 없는 제품(비노출·대외비)의 항목은 제외한다.
- 결과가 3개 미만이면 인기콘텐츠 영역을 렌더링하지 않는다.
- 결과는 수 분 캐싱하고 진입 시 갱신한다.

## 2. 인기콘텐츠 슬라이드 UI

- 위치: 히어로 아래, 제품 카드 그리드 위. 섹션 타이틀 "요즘 많이 본 콘텐츠".
- 형태: 가로 슬라이드, **한 화면에 카드 3장 동시 노출**(좁은 화면은 2.2장), 좌우 화살표 + 스와이프 + 스냅.
- 카드: 이미지 위 다크 스크림 + 제품명(레드, 소형) + 특장점 제목(화이트, 2줄) + 순위 배지(1~5).
- 조회수 숫자는 노출하지 않는다.
- 카드 전체가 터치 타깃이며 탭 즉시 해당 특장점 상세로 이동하고 기존 분석 이벤트를 기록한다.

## 3. 고정 캔버스 + 제품 카드 정리

- 홈 컨테이너를 `100dvh` + `overflow-hidden`으로 잡고 헤더 / 히어로 / 인기콘텐츠 / 제품 그리드를 세로 flex로 배분한다.
- 제품 그리드는 2열(넓은 화면 3열), 카드 상단 컬러 띠 제거, 패딩·라운드 정리, 설명 2줄 제한.
- 카드가 화면보다 많으면 그리드 영역 내부에서만 스크롤한다(외곽 고정 유지).
- 가로모드(`html[data-orientation="landscape"]`) 오버라이드도 동일 규칙으로 맞춘다.

## 기술 메모

- 브랜드 레드 #FD312E를 `index.css` 시맨틱 토큰으로 추가하고(예: `--brand-accent`) 하드코딩 없이 사용. 기존 `--brand`(#A50034)는 구독 페이지용으로 유지.
- 변경 파일: `src/pages/ProductSelection.tsx`(헤더 로고 락업·레이아웃·카드 리디자인·섹션 삽입), 신규 `src/components/PopularContentSlider.tsx`, 신규 `src/hooks/usePopularFeatures.ts`, `src/index.css`, `tailwind.config.ts`(토큰 등록).
- 백엔드: `page_views` 기반 집계 함수 1개 추가(읽기 전용, 기존 테이블·정책 변경 없음).
- 인기콘텐츠 매칭은 기존 `features.ts` ID 규칙을 그대로 사용한다.
