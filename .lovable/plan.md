## 목표
`src/data/branches.ts`의 `BRANCH_GROUPS`(담당별)와 `BRANCH_CODE_MAP`(코드)에 업로드된 일반매장 리스트를 추가한다. 기존에 부여된 매장 코드는 절대 변경하지 않고(대연점=DY, 담양점=DY2 등), 신규 매장 코드가 기존과 겹치면 뒷자리에 2/3/4… 를 붙여 구분한다.

## 변경 파일

### 2) 코드 부여 알고리즘
1. 매장명에서 "점", "(분점)", " " 등 접미사/공백/괄호 정리 후 한글 본문 추출 (영문 토큰 — "LG전자 플래그십 D5" — 은 영문/숫자 그대로 사용).
2. 각 음절의 초성을 영문 1자로 매핑(ㄱ→G, ㄴ→N, ㄷ→D, ㄹ→R, ㅁ→M, ㅂ→B, ㅅ→S, ㅇ→Y(또는 첫음절은 모음 그대로 처리하던 기존 규칙 유지), ㅈ→J, ㅊ→C, ㅋ→K, ㅌ→T, ㅍ→P, ㅎ→H) — 기존 `branches.ts` 코드와 동일 패턴 사용.
3. 베이스 코드는 보통 2~3자. 4글자 이상 매장명은 첫 글자+나머지 초성 결합.
4. **충돌 검사**: 생성한 코드가 이미 `BRANCH_CODE_MAP` 값으로 존재하면 뒤에 `2`, 그래도 충돌이면 `3`, `4`… 를 붙임.
5. **기존 매핑 보존**: `대연점→DY`, `베스트샵 담양점→DY2`, 그 외 모든 기존 키-값은 절대 수정/덮어쓰기 금지. 새 항목은 항상 객체 끝에 append.

### 3) 검증
편집 후 스크립트로 자체 검증:
- `Object.values(BRANCH_CODE_MAP)` 중 중복이 없을 것
- 기존 키 47+150개의 값이 사전 수정 전과 100% 동일할 것 (snapshot diff)
- `BRANCH_GROUPS` 의 모든 신규 매장명이 `BRANCH_CODE_MAP`에 키로 존재할 것
- `대연점` 매핑이 여전히 `DY`인지 명시적으로 assert

## 기술 메모
- 코드 생성은 일회성이므로 런타임이 아니라 편집 시점에 결정해 정적 객체로 박는다(검색·디버깅이 쉬워짐, 기존 코드 스타일과 동일).
- GA4 집계 키가 코드 기반이므로 기존 코드 변경은 데이터 단절을 일으킨다 → 보존이 핵심 제약.
- `DEALER_TO_BRANCH_MAP`은 이번 작업에선 변경하지 않음(거래선명 정보 미제공).

승인해 주시면 위 규칙대로 한 번에 추가하고, 검증 스크립트 결과(중복 0, 기존 키 보존 OK)를 같이 보고드리겠습니다.
